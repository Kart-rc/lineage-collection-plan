# G1 amendment 3: complete static snapshots and collection contracts

**Status: all four design directions were approved by the requesting user on
28 November 2026 with "approve all 4". These precise amendments are prepared for
human merge.** Keeping this record under `proposed/` prevents the checker from
treating it as a signed, merged gate. No G2/G3/G4 approval is implied.

| Approved direction | Precise amendment |
| --- | --- |
| Complete-unit snapshots | Add the unit-snapshot schema and protocol: reserve a durable generation before extraction, stage immutable metadata before the completion manifest, distinguish empty/deleted/incomplete results, and preserve merged/PR isolation with combined runtime/static recovery. |
| Expression changes | Add lineage.changes schema v2, `expression_changed` and explicit sorted unique old/new `expressionHashes`. Legacy v1 retains its original fields and kinds. |
| Repeatable manifest comparison | WP-18 compares normalized content excluding only `started`, `finished` and per-unit `duration_ms`; complete manifests retain real timings. Source, configuration and starting cache inputs must match. |
| Plugin fixtures | Add matching `lineage_ci.conformance` entry points returning `ConformanceFixture`; absent, invalid or failing fixtures prevent plugin loading. The three extractor methods and approved accuracy floors stay unchanged. |

The expression-hash schema retains existing envelope compatibility with 8–64
hexadecimal characters; producers should use full SHA-256. Independent owners
retain alternatives; replacing one owner's snapshot replaces only its contribution.
Readers must support v2 before producers emitting expression fields are enabled.

Validation must retain the legacy condition-change example and reject incomplete
snapshots, invalid routes and expression events labeled v1. Implementation checks
cover durable reservation, partial/duplicate/stale delivery, hash/count mismatch,
deletion, PR isolation, archive recovery and expression transitions on real Neo4j.

SQLite coordination and shared local objects are a single-writer twin reference
implementation, not certification of distributed consensus or multi-tenant access
control. G3-pinned oracles, thresholds, hard zeros and holdout custody are unchanged.
Docker Neo4j replaces stage Neptune under the earlier user instruction.
