# Source verification: commercial vendors

26 November 2026. Every quotation below was fetched directly from the vendor's own documentation site (no caches, readers or archives) to check the search-summary ("S") claims in `docs/05-vendor-assessment-element-level-lineage.md`.
48 requests were made: 42 returned content (34 distinct documentation pages, one of them read in two formats, plus 7 documentation index files), 5 were refused with HTTP 403 (IBM 3, Informatica 2) and 1 returned 404 (Gable's old CLI page). Two web searches were used, both to locate Collibra pages.

Verdict counts: 13 confirmed, 8 corrected, 7 not verifiable. Atlan, Monte Carlo, Datafold and Gable pages were read as the site's own markdown variant (`.md` or `llms.txt`); Atlan's variant drops status badges, as the HTML cross-check for T4 showed.

## Corrections that change the report

- **C3, Collibra.** Collibra's OpenLineage-based integrations are generic OpenLineage, Apache Airflow, AWS Glue and Alteryx (dbt Cloud and dbt Core are separate native integrations), and each synchronisation replaces a source's previously harvested lineage, so Collibra documents no lineage history and no diff between syncs.
- **T2, Atlan.** Atlan's own documentation says column lineage is created for direct (identity, calculated, aggregation) and conditional transformations and excludes JOIN, FILTER and GROUP BY; BigQuery stored procedures and scalar UDFs are cataloged and linked to Process nodes without becoming lineage-graph nodes, and dynamic SQL through `EXECUTE IMMEDIATE` and nested routine calls is not captured.
- **M2, Monte Carlo.** "MC Prevent" (GitHub only) posts a Low, Medium or High risk comment scored over six tunable weights, including lineage blast radius at 15% by default, and offers an optional CI merge gate for GitHub Actions or CircleCI that blocks once it is made a required status check (default policy `medium+`); the gate carries no experimental or preview label (only its configuration API is called experimental), a dbt integration is optional but needed to identify affected tables, and full reviews are chargeable above a free risk score and summary.
- **F2, Datafold.** Datafold's pull-request testing (a data-diff comment plus downstream BI and reverse-ETL assets, on GitHub, GitLab, Bitbucket and Azure DevOps) is documented only for Datafold Classic and is "not available in the current version of Datafold"; the only documented failing condition for its CI check is primary-key issues, so blocking on data differences remains unconfirmed.
- **O2, Foundational.** Foundational publishes extraction articles for Spark, Java, Scala, Kafka, .NET, mainframe COBOL, SQL (parsed with SQLGlot), SQLAlchemy, Doctrine, Ruby Active Record, Liquibase, TypeORM, Entity Framework Core and Python, with none for dbt in that collection, and its Spark lineage is produced "by simulating the code in a sandbox" and not by parsing alone (taken from the article summary; the Spark article was not opened).
- **O3, Foundational.** Foundational documents field-level Kafka lineage from producer, consumer, Kafka Streams and Kafka Connect code, using Avro, Protobuf and JSON Schema definitions to resolve fields across topics; this is a vendor claim and remains untested.
- **G1, Gable.** Gable's current documentation says static analysis runs through its CLI or GitHub Actions on a local checkout in the customer's development or CI environment and that "Code-level metadata is sent to the Gable platform"; the page that carried the "bundling and transmission of your code" sentence now returns 404, and what "code-level metadata" contains still needs a security review.
- **G3, Gable.** Gable's current documentation describes no contract checks, contract-violation pull-request comments or WARN and BLOCK enforcement; the only pre-merge feature it describes, per-merge impact reports in CI/CD, is marked "Coming soon" and "not yet generally available", so the BLOCK level rests on the CLI package source alone.
